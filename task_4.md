# Протоколы HTTP и HTTPS

## Основные шаги работы HTTPS

**Шаг 1: Инициация TLS-соединения**  
Клиент устанавливает TCP-соединение с сервером на порту 443 и инициирует TLS-рукопожатие, отправляя сообщение `ClientHello`, в котором указывает поддерживаемые версии протокола, криптографические алгоритмы и случайное число

**Результат:** Сервер получает запрос на установление защищённого соединения и отвечает сообщением `ServerHello`

**Шаг 2: Проверка сертификата безопасности**  
Сервер отправляет клиенту цифровой сертификат, выданный доверенным центром сертификации (CA). Сертификат содержит открытый ключ сервера и информацию о домене. Клиент проверяет цепочку доверия, срок действия сертификата и соответствие имени домена

**Результат:** Если сертификат действителен и доверенный, клиент продолжает рукопожатие; в противном случае соединение прерывается

**Шаг 3: Обмен криптографическими параметрами и генерация общего секрета**  
Клиент и сервер обмениваются параметрами для выработки общего секретного ключа. В зависимости от используемой версии TLS и набора шифров это может включать:
- Обмен эфемерными ключами Диффи–Хеллмана (ECDHE), обеспечивающий forward secrecy
- Или (в устаревших схемах) шифрование предварительного секрета открытым ключом сервера

**Результат:** Обе стороны независимо вычисляют одинаковый мастер-секрет (master secret), который используется для генерации симметричных ключей шифрования и MAC

**Шаг 4: Подтверждение завершения рукопожатия**  
Клиент и сервер отправляют сообщения `Finished`, зашифрованные с использованием только что созданных ключей. Это подтверждает, что обе стороны обладают одинаковым секретом и соединение безопасно

**Результат:** TLS-рукопожатие завершено; устанавливается зашифрованный канал

**Шаг 5: Начало шифрованного обмена данными**  
Только после успешного завершения TLS-рукопожатия клиент отправляет HTTP-запрос (например, `GET / HTTP/1.1`). Все последующие данные — заголовки, тело запроса и ответа — шифруются симметричным ключом

**Результат:** Конфиденциальные данные (логины, пароли, платёжная информация) передаются в зашифрованном виде

**Шаг 6: Завершение сессии**  
По окончании взаимодействия соединение закрывается. Сессионные ключи уничтожаются, что обеспечивает свойство *forward secrecy* — компрометация долгосрочных ключей не позволяет расшифровать прошлые сессии

**Результат:** Сеанс завершён, временные ключи удалены, безопасность сохранена

## Группы кодов состояния HTTP

### 1XX: Информационные коды  
Указывают на промежуточное состояние обработки запроса. Обычно обрабатываются автоматически

- **100 Continue** — сервер готов принять тело запроса
- **101 Switching Protocols** — сервер согласен переключить протокол (например, на WebSocket)
- **102 Processing** — запрос принят и находится в обработке (расширение WebDAV, не входит в стандарт HTTP/1.1)

### 2XX: Успешные коды  
Запрос успешно обработан

- **200 OK** — стандартный успешный ответ  
- **201 Created** — ресурс успешно создан
- **202 Accepted** — запрос принят, но ещё не обработан полностью 
- **204 No Content** — запрос обработан, но тело ответа отсутствует

### 3XX: Коды перенаправления  
Клиент должен предпринять дополнительные действия для завершения запроса

- **301 Moved Permanently** — ресурс перемещён на новый постоянный URI
- **302 Found** — временный редирект (в исходной спецификации — «Moved Temporarily») 
- **304 Not Modified** — ресурс не изменился с указанной даты; клиент может использовать кэшированную версию. Не является перенаправлением в обычном смысле, но формально относится к группе 3xx

### 4XX: Ошибки клиента  
Запрос содержит ошибку или не может быть выполнен по причине на стороне клиента

- **400 Bad Request** — сервер не может обработать запрос из-за неверного синтаксиса  
- **401 Unauthorized** — требуется аутентификация  
- **403 Forbidden** — доступ к ресурсу запрещён, даже при наличии учётных данных  
- **404 Not Found** — запрашиваемый ресурс не найден

### 5XX: Ошибки сервера  
Сервер не смог выполнить корректный запрос из-за внутренней ошибки

- **500 Internal Server Error** — общая ошибка обработки на сервере  
- **502 Bad Gateway** — сервер, выступающий в роли шлюза или прокси, получил недопустимый ответ от вышестоящего сервера  
- **503 Service Unavailable** — сервер временно не может обработать запрос (перегрузка, техническое обслуживание)  
- **504 Gateway Timeout** — шлюз не дождался ответа от вышестоящего сервера в отведённое время
